# MySQL 规范（参考《阿里巴巴开发手册》）

> 本规范摘录并结合《阿里巴巴 Java 开发手册（泰山版）》中与 MySQL 设计、开发、运维相关的核心要求，供团队在设计登录/注册等核心数据模型时遵循。

## 命名规范
- 表名、字段名全部小写，使用下划线分隔，禁止使用复数；如 `t_user_auth`。
- 统一为业务实体增加前缀 `t_` 或 `rel_` 等标识，避免与系统关键字冲突。
- 索引、唯一键命名以 `idx_字段`、`uk_字段` 形式出现，便于快速识别用途。
- 临时表以 `tmp_` 开头并在当天清理；备份表以 `bak_` 开头并注明日期。

## 表设计规范
- 每张表必须有自增主键或使用雪花 ID，禁止以业务字段作为主键。
- 避免单表列数超过 50，确保每张表字段职责单一；大字段（BLOB/CLOB）独立拆表。
- 必须为表增加 `gmt_create`、`gmt_modified` 或 `created_at`、`updated_at` 等时间戳字段，默认值为 `CURRENT_TIMESTAMP`。
- 建议所有整型字段设置 `unsigned`（如非负）以提升可表示范围。
- **所有表和字段必须添加中文或英文注释（COMMENT）**，明确业务含义，便于运维和审计。

## 字段定义规范
- 字段类型精确到最小粒度：金额统一用 `DECIMAL(18,4)`，禁止使用 `FLOAT/DOUBLE` 存货币。
- 字符串字段根据长度选择 `CHAR` 或 `VARCHAR`；可变长度或会发生字符集转换的使用 `VARCHAR`。
- 使用 `TINYINT` 存储布尔或枚举型字段，统一约定含义（如 0-否、1-是）。
- 所有字段必须设置 `NOT NULL`，并提供默认值；确需允许为空的场景需在设计文档中说明。

## 索引与性能
- 依据最左前缀原则创建联合索引；WHERE、ORDER BY、GROUP BY 中出现的列必须有索引。
- 控制单张表索引数量，建议不超过 5 个；联合索引字段数不超过 5，避免过宽索引。
- 禁止出现 `SELECT *`；查询列必须显式列出，减少返回数据量。
- 大批量写入时采用批处理或分批提交（每批不超过 1000 条）。

## SQL 使用规范
- WHERE 条件必须使用参数化或预编译，禁止直接拼接用户输入，防止 SQL 注入。
- 禁止在数据库端做过度计算：复杂逻辑放在业务层处理，数据库仅负责 CRUD。
- 分页查询必须带 ORDER BY，且建议使用覆盖索引或延迟关联控制分页深度。
- 对于 `IN` 条件的集合参数，元素个数控制在 1000 以内，超出范围分批查询。

## 运维与安全
- 数据库字符集统一为 `utf8mb4`，与 JDBC 连接配置保持一致。
- 严格控制线上 DDL：所有结构变更通过 Flyway 等版本化脚本执行，不允许手工改表。
- 核心表需开启 binlog，定期备份并验证恢复流程；对敏感操作做好审计。
- 生产库与测试库隔离，禁止直接连接生产库做开发调试。

> 若业务场景有特殊需求，可在评审通过后另行补充，但不得违反以上底线要求。
