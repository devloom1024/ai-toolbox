## 二、持仓收益自动更新机制

### 2.1 更新触发方式

```
┌─────────────────────────────────────────────────────────────┐
│  持仓收益更新机制                                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 定时自动更新（推荐）                                     │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                                                     │   │
│  │  交易时段（9:30-15:00）：每 5 分钟刷新一次          │   │
│  │  收盘后（15:00 后）：一次性刷新全部持仓             │   │
│  │  非交易时段：每 30 分钟刷新一次                     │   │
│  │                                                     │   │
│  │  优点：用户打开页面时数据已是最新                   │   │
│  │  缺点：服务端资源消耗较大                           │   │
│  │                                                     │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  2. 用户主动刷新（补充）                                     │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                                                     │   │
│  │  页面下拉刷新 / 刷新按钮                            │   │
│  │  用户进入持仓详情页时自动刷新                       │   │
│  │  定时器倒计时后自动刷新（用户可配置）               │   │
│  │                                                     │   │
│  │  优点：按需更新，节省资源                           │   │
│  │  缺点：用户需主动操作                               │   │
│  │                                                     │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
│  3. 数据变化触发（实时）                                      │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                                                     │   │
│  │  用户进行加仓/减仓操作后立即更新                     │   │
│  │  用户手动修改持仓成本后立即更新                      │   │
│  │  价格突破用户设置的阈值时更新并推送                  │   │
│  │                                                     │   │
│  │  优点：数据变化及时响应                             │   │
│  │  缺点：需要额外的推送机制                           │   │
│  │                                                     │   │
│  └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 更新计算逻辑

```
┌─────────────────────────────────────────────────────────────┐
│  收益计算逻辑                                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  【股票/ETF 持仓】                                           │
│                                                             │
│  步骤 1：获取最新价格                                        │
│  price = getLatestPrice(symbol)                             │
│                                                             │
│  步骤 2：计算市值                                            │
│  current_value = shares × price                             │
│                                                             │
│  步骤 3：计算收益                                            │
│  profit = current_value - (shares × avg_cost)                │
│                                                             │
│  步骤 4：计算收益率                                          │
│  profit_rate = profit / (shares × avg_cost)                  │
│                                                             │
│  ────────────────────────────────────────────────────────  │
│                                                             │
│  【基金持仓】                                                │
│                                                             │
│  步骤 1：获取最新净值                                        │
│  nav = getLatestNav(fund_code)                              │
│                                                             │
│  步骤 2：计算市值（用户自行更新金额和收益）                    │
│  current_value = amount + profit                            │
│                                                             │
│  步骤 3：计算收益率                                          │
│  profit_rate = profit / amount                              │
│                                                             │
│  【注意】基金需要用户手动更新金额和收益                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 定时任务设计

```java
@Configuration
public class PositionUpdateScheduleConfig {
    
    // 交易时段：每 5 分钟刷新
    @Scheduled(cron = "0 0/5 9-15 * * MON-FRI")
    public void tradingHoursUpdateTask() {
        // 更新所有持仓的实时价格和收益
        positionService.updateAllPositionsDuringTrading();
    }
    
    // 收盘后：一次性刷新全部
    @Scheduled(cron = "0 30 15 * * MON-FRI")
    public void afterCloseUpdateTask() {
        // 更新所有持仓（收盘价）
        positionService.updateAllPositionsAfterClose();
    }
    
    // 非交易时段：每 30 分钟刷新
    @Scheduled(cron = "0 0/30 0-9,15-23 * * *")
    public void nonTradingHoursUpdateTask() {
        // 只更新有持仓的标的
        positionService.updateActivePositions();
    }
}
```

## 三、核心业务规则

### 3.1 账号类型规则

| 账号类型 | 枚举值 | 说明 | 典型场景 |
|----------|--------|------|----------|
| 券商 | BROKER | 券商平台账号 | 股票、场内ETF |
| 基金平台 | FUND_PLATFORM | 基金销售平台 | 场外基金 |
| 支付宝 | ALIPAY | 支付宝理财 | 基金、理财 |
| 银行 | BANK | 银行账号 | 银行理财 |
| 其他 | OTHER | 其他平台 | 雪球、东方财富等 |

### 3.2 持仓类型规则

| 场景 | 股票/ETF | 基金 |
|------|----------|------|
| 适用账号类型 | BROKER/OTHER | FUND_PLATFORM/ALIPAY/BANK |
| 录入字段 | 份额 + 成本价 | 金额 + 收益 |
| 市值计算 | 份额 × 现价 | 金额 + 收益 |
| 成本价 | 平均成本价 | 不适用 |
| 收益率 | (市值-成本)/成本 | 收益/金额 |

### 3.3 成本计算规则

**加仓后平均成本**：
```
新平均成本 = (原份额×原成本 + 新份额×新价格) / (原份额+新份额)
```

**减仓后成本**：
- 减仓不影响剩余持仓的成本价
- 仅更新剩余份额和市值

### 3.4 置信度规则

| 置信度 | 含义 | 建议操作 |
|--------|------|----------|
| 90-100% | 信号明确 | 重点关注，可适当加大仓位 |
| 70-89% | 信号较强 | 建议关注，正常仓位 |
| 50-69% | 信号中性 | 仅供参考，需结合其他信息 |
| 30-49% | 信号较弱 | 谨慎操作，小仓位试探 |
| < 30% | 信号不明确 | 建议观望 |

## 四、核心数据流

### 4.1 账号数据流

```
用户添加账号 → t_account（账号表）
  │
  ├── 账号启用/隐藏 → 控制显示
  └── 账号排序 → 控制列表顺序
```

### 4.2 持仓数据流

```
用户录入持仓 → 选择账号 → t_position（持仓表，关联account_id）
  │
  ├── 加仓操作 → t_position_trade（交易记录表，关联account_id）
  │     └── 更新 t_position（平均成本）
  │
  └── 减仓操作 → t_position_trade（交易记录表，关联account_id）
        └── 更新 t_position（剩余份额、市值）
```

### 4.3 查询数据流

```
查询持仓列表
  │
  ├── 单账号查询 → WHERE account_id = ?
  └── 全账号查询 → WHERE user_id = ?（可按标的汇总）

查询持仓详情
  │
  ├── 获取持仓基本信息
  ├── 获取该账号的交易记录
  └── 汇总所有账号的该标的持仓（用于AI分析）
```

### 4.4 AI 分析数据流

```
API 请求（symbol + user_id）
  │
  └── 查询该用户在所有账号的该标的持仓
        │
        └── 汇总：总份额、总成本、总投资金额
              │
              └── 构建 Prompt（含汇总数据）
                    │
                    └── 调用 LLM
                          │
                          └── 返回分析结果（含账号明细）
```
